# 개발일지 — 글로벌 사업장 HDPS KPI 자동집계·미달성 메일링 (hd-project11)

- 프로젝트: 글로벌 6개 사업장 HDPS KPI 자동집계 + 달성/미달성 판정 + 미달성 자동 메일링
- 기획: 서지철 (HD건설기계, Lean 컨설팅 담당)
- 개발일: 2026-08-24
- 저장소: https://github.com/aebonlee/hd-project11

## 1. 요구사항 분석

이 프로젝트는 **백지에서 시작한 기획이 아니었다.** 기획자가 이미 엑셀 VBA 매크로로
한 번 만들어 운영 중이었고, 2026-08-24에 "매크로, 파이썬만 활용했는데 원하는 대로 잘
안 나오네요"라고 막힌 상태로 자료를 넘겨 왔다.

받은 자료(`rereadme_md.zip`)를 열어 보니 실제 요구사항은 기획서 문장이 아니라
**기획자가 스스로 정리해 둔 `셀프운영_가이드.md`(v3)** 에 있었다. 거기 "오늘 새로 고친 것"
다섯 항목이 곧 매크로가 넘어졌던 자리였다.

| # | 매크로가 틀렸던 자리 |
|---|---|
| 1 | 값이 100배 차이 — 원본 `0.96`(소수) vs 총괄 `96`(정수) |
| 2 | `"00:48:00"` 같은 시간 형식(MTTR/MTBF/MTTD) |
| 3 | `"+8%"` 같은 퍼센트 텍스트 |
| 4 | `"제외"` 같은 텍스트를 숫자와 비교하다 Type Mismatch |
| 5 | 대상 파일이 다른 창에 열려 있으면 오작동 |

**그래서 이 프로젝트의 진짜 목표는 "KPI 대시보드를 만드는 것"이 아니라
"이 다섯 가지가 다시는 조용히 틀리지 않게 고정하는 것"으로 잡았다.**
전부 단위 테스트로 옮겼다.

받은 자료 구성:

- `HDPS_KPI_자동화_설정워크북.xlsm` — 매핑표 2개(인도 104행·브라질 80행), 담당자메일, 실행로그
- `modImport_코드.txt` / `modCheck_코드.txt` / `modMail_코드.txt` — VBA 3모듈
- `셀프운영_가이드.md` — 설치·실행 4단계 + 트러블슈팅
- 총괄파일(사업장 9시트) + 인도·브라질 원본 KPI 파일 2개

## 2. 설계 결정

| 결정 | 이유 |
|---|---|
| **행 번호가 아니라 KPI 이름으로 찾는다** | 매크로는 `원본행`·`원본 실적행`에 행 번호를 박아 뒀다. 원본 서식에서 행이 한 줄만 밀려도 엉뚱한 값을 읽는다. 이름으로 찾으면 밀려도 맞는다 |
| 순수 HTML/JS + localStorage | 빌드 없이 Pages에 올라가고, 사내에서 파일만 열어도 돈다. 매크로 설치(모듈 3개 가져오기)가 없어지는 것이 기획자에게 가장 큰 차이 |
| 계산을 `js/logic.js`(UMD)로 분리 | 값 변환·판정·메일 초안을 Node에서 단위 테스트. 화면 없이도 검증된다 |
| 메일은 `mailto:` (자동 발송 아님) | 브라우저에서 SMTP 직접 발송은 불가능하다. 다만 매크로도 기본값이 `SEND_DIRECTLY = False`(검토 후 발송)였으므로 **동작이 오히려 같다** |
| **달성률 분모에서 미입력을 뺀다** | 실적이 아직 안 온 지표를 미달성으로 세면 자료가 늦는 달마다 달성률이 통째로 무너져 보인다. 화면에서도 미입력과 미달성을 따로 센다 |
| gap 부호를 "양수면 좋은 쪽"으로 통일 | 하향 지표(대당 비가동 MH 등)에서도 목표보다 낮으면 gap이 양수가 된다. 메일 본문을 방향별로 다르게 쓸 필요가 없어진다 |
| **실데이터를 저장소에 넣지 않는다** | 기획자가 "저만 관리하는 자료인데 반출할 수가 없어서"라고 두 번 명시했다. 저장소는 public이다 |

## 3. 구현 내역

1. **로직**(`js/logic.js`) — 값 변환(환산배율·시간serial·퍼센트텍스트·텍스트 거르기),
   매핑 적용(전사/건너뜀/누락 3분류), 판정 4방향(상향·하향·목표일치·범위내),
   월 단위 집계, 모듈별 요약, 12개월 추이, 담당팀 분해, 메일 초안 생성.
2. **화면** — 대시보드 / ① 데이터 자동입력 / ② 달성 판정 / ③ 미달성 메일링 /
   매핑표 / 담당자 / 실행로그 7개 탭.
3. **임포트**(`js/importer.js`) — 워크북 전 시트 파싱, KPI 이름 열 자동 탐지,
   값 열 후보 점수화(숫자 밀도 순), 표준 양식 엑셀 생성.
4. **더미 시드** — 사업장 6곳 × KPI 120개 × 12개월 = 720지표.
   HDPS 표준 19개 모듈 체계(5S·TPM·VSM·LOB·EHS 등)와 실제 지표명 구조는 살리고
   **목표·실적은 전부 생성기가 만든 가짜**.
5. **생성기**(`scripts/gen-seed.py`) — 시드를 다시 굽는 스크립트.
   결정적 의사난수를 써서 다시 구워도 같은 결과가 나온다(멱등 확인함).

## 4. 테스트 및 검증

`node test/logic.test.js` — **86개 통과**.

- 값 변환: 환산배율 100/1, 문자열 숫자, 천단위 쉼표, 시간serial 3종, 퍼센트텍스트 2종,
  `"제외"`/`"TBD"`/`"확인필요"`/빈값 거르기, 배율 0·null 방어
- 매핑: 전사/건너뜀/누락 3분류, 대소문자·공백 흔들림 흡수
- 판정: 4방향 × 경계값, gap 부호, 판정불가 3종
- 월 집계: 미입력 분리, 자료 없는 달의 달성률 `null`(0%가 아님)
- 담당팀: 줄바꿈·쉼표·슬래시 분해, 두 팀 담당 지표가 양쪽에 들어가는지
- 메일: 수신자 유무에 따른 발송 준비/대기, 호칭, 본문 항목
- 시드 정합성: 사업장 6곳, KPI 100개 이상, 목표가 전부 숫자, id 중복 0, 미달성 존재

**깨뜨리기 테스트** — 통과만 확인한 테스트는 통과해도 의미가 없으므로 세 가지를 일부러 심었다.

| 심은 결함 | 잡힌 실패 |
|---|---|
| 환산배율을 곱하지 않게 | 1건 |
| 하향 판정을 뒤집기 (`a <= t` → `a > t`) | 11건 |
| 미입력을 달성률 분모에 포함 | 2건 |

셋 다 잡혔다. 다만 하향 판정을 뒤집었을 때 **6번째 검사에서 예외가 나며 출력이 잘려**
진짜 원인이 안 보였다. 앞 단계가 깨지면 뒤 검사가 터지지 않도록 두 곳을 방어했다
(메일 초안이 비었을 때, 미달성 건수가 모자랄 때). 이제 11건이 전부 출력된다.

추가로 `node --check` 전 파일 통과, Store 왕복 스모크(저장→재로드→실적·담당자·로그 보존) 확인.

## 5. 트러블슈팅

| 이슈 | 해결 |
|---|---|
| **zip 안 한글 파일명이 깨져 압축이 안 풀림** | `unzip`이 `Illegal byte sequence`로 거부. CP437→CP949로 다시 디코드하고 NFC 정규화해서 파이썬으로 풀었다 |
| **원본에 `"96%"`처럼 이미 퍼센트인 값이 섞임** | 환산배율 100을 또 곱하면 `9600`이 된다. 기획자 가이드에 없던 여섯 번째 함정. 퍼센트 기호가 있고 배율이 100이면 곱하지 않도록 하고 테스트를 걸었다 |
| **첫 화면이 온통 "미입력"으로 보임** | 기본 기준월을 "값이 하나라도 있는 마지막 달"로 잡았더니 자료가 막 들어오기 시작한 12월(45/120 미입력)이 잡혔다. **채움률 80% 이상인 마지막 달**로 바꿔 9월이 잡히게 했다. 실제 업무의 보고 기준월도 직전 마감월이다 |
| 매핑표 영문 모듈 표기가 갈림 | `Materials supply`/`Material Supply`, `Zero defects`/`Zero Defect`, `Standard work`/`Standardized Work` — 21개 표기를 19개 정규 모듈로 눌렀다 |

## 7. 향후 과제 (교육 당일 확인할 것)

기획자가 "해당 파일은 제 전용 파일이나, 사내 보안으로 교육당일 공유 가능합니다"라고 했으므로
당일 실물을 보고 아래를 맞춘다.

1. **사업장 목록 확정** — 현재 더미 6곳(울산·인천·군산·인도·브라질·유럽).
   실제 이름으로 바꾸려면 `scripts/gen-seed.py` 의 `SITES` 만 고치면 된다.
2. **목표값이 연간 고정인가 월별로 다른가** — 현재는 연간 고정.
3. **"범위내" 판정의 허용 오차** — 현재 기본 ±5%.
4. 미달성 회신(사유·만회대책)을 시스템에서 **받아 관리**할 필요가 있는지 — 현재는 발송까지만.
5. 사내 Outlook/Exchange 자동 발송이 정책상 가능한지 — 가능하면 Edge Function으로 붙인다.
6. 지표별 담당이 팀 단위가 아니라 개인 단위인 경우가 있는지.
