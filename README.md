# 글로벌 사업장 HDPS KPI 자동집계·미달성 메일링 (hd-project11)

> 🌐 **배포 페이지: [https://aebonlee.github.io/hd-project11/](https://aebonlee.github.io/hd-project11/)** · 저장소: https://github.com/aebonlee/hd-project11

> 기획: 서지철 (HD건설기계) · 생성형 AI 업무자동화 전문가과정 [1차수] 프로젝트

글로벌 6개 사업장이 매달 보내오는 **KPI 원본 엑셀을 올리면 자동으로 전사**되고,
목표 대비 **달성/미달성이 자동 판정**되며, 미달성 지표는 **담당팀별로 묶여
사유·만회대책 요청 메일 초안까지 자동 작성**되는 웹 포털입니다.

기획자가 직접 만든 **엑셀 VBA 매크로 3모듈**(`modImport` / `modCheck` / `modMail`)을
웹으로 옮긴 것입니다. 매크로가 실제로 걸려 넘어졌던 자리를 전부 테스트로 고정했습니다.

- 빌드 없이 동작하는 순수 HTML/CSS/JS — GitHub Pages에 그대로 올라갑니다
- 저장소는 두 가지 모드: **데모 모드**(브라우저 `localStorage`) / **Supabase 모드**(공용 Postgres).
  화면과 계산은 같고 저장 위치만 다릅니다 → [`supabase/README.md`](supabase/README.md)
- 엑셀 읽기/쓰기: [SheetJS](https://sheetjs.com/) 로컬 동봉 (CDN 미사용 — 사내망에서도 열립니다)
- 메일 발송: `mailto:` 로 메일 클라이언트를 열어 **사람이 확인 후 발송**
  (매크로의 기본값 `SEND_DIRECTLY = False`와 같은 취지)

> ⚠️ **이 저장소에는 사내 실데이터가 없습니다.**
> 사업장·지표명·모듈은 HDPS 표준 체계를 따르지만 **목표·실적 수치는 전부 생성기가 만든 더미**입니다.
> 실제 KPI 파일을 이 저장소에 커밋하지 마세요 — 저장소가 public입니다.
> 실데이터는 **각자 브라우저에서 엑셀을 올려** 쓰면 되고, 그 값은 서버로 가지 않고
> 본인 브라우저의 localStorage에만 남습니다.

## 4단계 사용법

매크로의 "매달 하실 일 요약" 4단계와 순서가 같습니다.

### ① 데이터 자동입력 — `ImportOverseasData` 대체

1. 상단에서 **사업장**과 **기준월**을 고릅니다.
2. **① 데이터 자동입력** 탭 → 원본 KPI 엑셀(.xlsx/.xlsm) 선택.
3. 시트를 고르면 **KPI 이름이 가장 많이 맞는 열을 자동으로 찾아** 알려 줍니다.
   `A열에서 매핑표와 일치하는 지표명 77건을 찾았습니다` 처럼 나옵니다.
4. **실적 값 열**을 고릅니다(숫자가 많이 든 열이 위로 옵니다). → **[전사 실행]**
5. 결과가 **전사 대상 / 건너뜀 / 매핑 누락** 세 갈래로 나옵니다.
   건너뛴 값은 사유(`제외 지표`, `숫자 아님(확인필요)`, `빈값`)까지 표시됩니다.
6. 확인 후 **[이 결과를 실적에 반영]**.

> **원본 서식이 너무 달라 인식이 안 될 때**: **[표준 양식 내려받기]** 로 받은 엑셀의
> `실적` 열만 채워 올리면 항상 읽힙니다.

> 매크로는 `원본행(레이블)` · `원본 실적행(actual_row)` 처럼 **행 번호를 박아 두고** 읽었습니다.
> 원본에서 행이 한 줄만 밀려도 엉뚱한 값을 읽었는데, 이 웹판은 **이름으로 찾으므로** 밀려도 맞습니다.

### ② 달성 판정 — `CheckAchievement` 대체

1. **② 달성 판정** 탭 → 지표별 목표 vs 실적이 판정과 함께 표시됩니다.
   달성은 초록, 미달성은 빨강 행 — 매크로가 총괄파일 셀에 칠하던 색과 같습니다.
2. 모듈·상태로 걸러 볼 수 있습니다.
3. **[판정 결과 엑셀]** → `판정결과` + `미달성목록` 2시트로 저장됩니다.
   (매크로가 설정워크북에 만들던 "미달성목록" 탭에 해당합니다.)

### ③ 미달성 메일링 — `SendUnderperformanceEmails` 대체

1. 먼저 **담당자** 탭에서 팀별 이메일을 채웁니다(입력 즉시 저장).
2. **③ 미달성 메일링** 탭 → 미달성 지표가 **담당팀별로 묶여** 초안이 만들어집니다.
   `생산팀\n혁신팀` 처럼 두 팀이 담당인 지표는 **양쪽 초안에 모두** 들어갑니다.
3. 이메일이 등록된 팀은 **발송 준비**, 없으면 **이메일 미등록**으로 표시됩니다.
4. **[메일 열기]** → 메일 클라이언트가 제목·본문이 채워진 채로 열립니다. 확인 후 보내세요.
   **[본문 복사]** 로 그룹웨어에 붙여 넣어도 됩니다.
5. **[초안 전체 엑셀로]** → 메일머지용 표로 받습니다.

### ④ 확인

**대시보드**에서 6개 사업장 달성률, 모듈별 현황, 12개월 추이, 미달성 상위 지표를 봅니다.
**실행로그** 탭에 임포트·판정·메일 이력이 남습니다.

## 매크로 ↔ 웹 대응표

| VBA 매크로 | 웹 화면 | 로직 함수 |
|---|---|---|
| `modImport.ImportOverseasData` | ① 데이터 자동입력 | `Logic.convertValue` / `Logic.applyMapping` |
| `modCheck.CheckAchievement` | ② 달성 판정 | `Logic.judge` / `Logic.evaluateMonth` |
| `modMail.SendUnderperformanceEmails` | ③ 미달성 메일링 | `Logic.groupByOwner` / `Logic.buildMailDrafts` |
| 설정워크북 `매핑_인도` / `매핑_브라질` | 매핑표 탭 | — |
| 설정워크북 `담당자메일` | 담당자 탭 | — |
| 설정워크북 `실행로그` | 실행로그 탭 | `Store.log` |
| 총괄파일 셀 초록/빨강 칠하기 | 판정 표의 행 배경 | — |
| 설정워크북 `미달성목록` 탭 | 판정 결과 엑셀 2번째 시트 | `Logic.collectUnderperformance` |

**웹으로 옮기면서 없어진 문제**

- 대상 파일이 다른 창에 열려 있어 오작동하던 것 → 파일을 잠그지 않으므로 해당 없음
- "총괄파일이 안 열리거나 튕긴다" → 원본 엑셀을 고쳐 쓰지 않으므로 해당 없음
- 매크로 설치(모듈 3개 가져오기, .xlsm 저장) → 주소만 열면 됨

## 매크로가 틀렸던 자리 5가지

기획자의 `셀프운영_가이드.md`(v3)에 적힌 다섯 가지를 전부 테스트로 고정했습니다.

| # | 증상 | 처리 |
|---|---|---|
| 1 | 값이 **100배 차이** — 원본 `0.96` vs 총괄 `96` | 매핑표 **환산배율**을 곱함 |
| 2 | `"00:48:00"` 같은 시간 표기 | 값형식 `시간serial` → 시간 단위 숫자 |
| 3 | `"+8%"` 같은 퍼센트 텍스트 | 값형식 `퍼센트텍스트` → 숫자 |
| 4 | `"제외"` 등 텍스트를 숫자와 비교하다 **Type Mismatch** | 사유와 함께 `null`로 걸러 냄 |
| 5 | 대상 파일 중복 열림 | 해당 없음 |

**여기에 하나 더 잡았습니다.** 원본에 `"96%"` 처럼 **이미 정수 퍼센트로 적힌 값**이 섞여 오면,
환산배율 100을 또 곱해 `9600`이 됩니다. 웹판은 이 경우를 따로 잡습니다.
(`test/logic.test.js` — "이미 퍼센트로 적힌 값에 배율을 또 곱하지 않는다")

## 판정 규칙

| 판정방향 | 달성 조건 |
|---|---|
| 상향(높을수록 좋음) | 실적 ≥ 목표 |
| 하향(낮을수록 좋음) | 실적 ≤ 목표 |
| 목표일치 | \|실적 − 목표\| ≤ 허용오차 (기본 목표의 5%) |
| 범위내 | 목표일치와 같음. 허용오차를 지표별로 지정 가능 |

- **판정불가**: 실적이나 목표가 없거나 숫자가 아닌 경우.
- **달성률 = 달성 ÷ (달성 + 미달성)** — 판정불가는 분모에서 뺍니다.
  실적이 아직 안 들어온 지표를 미달성으로 세면 **자료가 늦게 오는 달마다 달성률이 통째로 무너져
  보입니다.** 그래서 미입력과 미달성을 화면에서도 따로 셉니다.
- **차이(gap)의 부호는 방향과 무관하게 "양수면 좋은 쪽"** 입니다.
  하향 지표에서 목표보다 낮으면 gap이 양수가 되므로, 메일 본문을 방향별로 다르게 쓸 필요가 없습니다.

## 실데이터로 쓰는 법

이 저장소는 public이므로 **실데이터를 커밋하지 않습니다.** 대신 두 가지 방법이 있습니다.

**1) 브라우저에서만 쓰기 (권장, 지금 바로 가능)**

배포 주소를 열고 ① 탭에서 실제 KPI 엑셀을 올리면 됩니다.
값은 **서버로 가지 않고** 본인 브라우저의 localStorage에만 저장됩니다.
다른 사람 화면에는 보이지 않고, [데모 초기화] 를 누르면 지워집니다.

**2) 사내 전용본으로 분리하기**

- 이 저장소를 **private으로 복제**한 뒤 `js/seed-data.js` 를 실제 사업장·지표·목표로 교체합니다.
- 시드는 손으로 고치지 말고 **`scripts/gen-seed.py` 를 고쳐 다시 굽습니다.**
  산출물만 고치면 다음에 스크립트를 돌릴 때 통째로 날아갑니다.

  ```bash
  python3 scripts/gen-seed.py
  ```

- 사업장 목록·팀 이름은 `scripts/gen-seed.py` 상단의 `SITES` / `OWNERS` 만 바꾸면 됩니다.

**3) 여러 사람이 같이 쓰려면 (Supabase 모드)**

이미 만들어 두었습니다. 절차는 [`supabase/README.md`](supabase/README.md) 를 보세요. 요약하면:

1. `supabase/schema.sql` 을 Supabase SQL Editor 에서 실행 (테이블 7종 + 함수 3종 + 뷰 3종 + RLS)
2. `hdp11_admin` 에 관리자 계정 등록
3. `js/config.js` 의 `USE_SUPABASE` 를 `true` 로 — 또는 주소에 `?supabase=1` 을 붙여 미리 확인

읽기는 로그인 사용자 전체, 쓰기는 관리자만, 실행로그는 **고치거나 지울 수 없습니다.**
연결에 실패하면 화면이 비지 않고 **데모 데이터로 내려가며 상단 띠에 이유를 적습니다.**

`js/store.js`(데모)와 `js/supabase-store.js`(운영)가 **같은 모양의 API** 를 내놓고,
`js/app.js` 는 `DB` 변수 하나만 보고 씁니다. `js/logic.js` 는 저장소를 아예 모릅니다.

## 개발 / 테스트

```
index.html            # 단일 페이지 앱 (탭 전환)
css/style.css         # 라이트 코퍼레이트 스타일
js/logic.js           # 순수 로직 (값 변환·판정·메일 초안) — Node 테스트 대상
js/store.js           # localStorage 데모 DB
js/importer.js        # 엑셀 읽기·열 자동 탐지·표준 양식
js/app.js             # 화면 컨트롤러
js/seed-data.js       # 자동 생성된 더미 (직접 고치지 말 것)
js/config.js          # Supabase 접속 설정 / 모드 전환
js/supabase-store.js  # Supabase 어댑터 (store.js 와 같은 API)
supabase/schema.sql   # 운영 스키마 + RLS  ← SQL Editor 에서 실행
supabase/README.md    # 설정 절차
scripts/gen-seed.py   # seed-data.js 를 굽는 생성기
scripts/kpi-catalog.json  # 모듈·지표명·판정방향·환산배율·값형식
scripts/sqltest/      # SQL 로컬 검증 하네스 (운영 실행 금지 가드 내장)
lib/xlsx.full.min.js  # SheetJS 로컬 동봉본
test/logic.test.js    # 단위 테스트
```

Node.js만 있으면 됩니다.

```bash
node test/logic.test.js      # 로직 86개
./scripts/sqltest/run.sh     # SQL 40여 개 (임시 PostgreSQL 을 띄워 실제 적용)
```

값 변환 6종(환산배율·시간·퍼센트텍스트·텍스트 거르기), 매핑 적용, 판정 4방향,
월 단위 집계(미입력 분리), 담당팀 분해, 메일 초안, 시드 정합성까지 **86개**를 검사합니다.

> 이 테스트는 **일부러 깨뜨려 통과 여부를 확인**했습니다.
> 환산배율 무시 / 하향 판정 반전 / 미입력을 분모에 포함 — 세 가지를 각각 심었을 때
> 1건·11건·2건씩 실패를 잡았습니다. 통과만 확인한 테스트는 통과해도 의미가 없습니다.
